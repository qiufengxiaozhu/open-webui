AI 故障诊断平台（RCA）— 产品需求规格说明

基于 OpenWebUI + 大模型语义路由 Skills + 日志/OCR 预处理
v1.0  |  2026-05-20  |  配套：技术方案文档

01. 需求背景与目标

1.1 痛点

  • 日志分散在多节点，人工关联耗时；故障知识存在于少数专家脑中
  • 报错截图需人工识别文字；缺乏标准化排查流程，MTTR 居高不下

1.2 定位

企业内部 AI 运维诊断助手 / Root Cause Analysis（RCA）系统

核心价值：领域化 Skills（语义路由）+ 日志故障分析。区别于通用 RAG 知识库。

1.3 目标

指标目标
故障定位时间缩短 60%（2h → 45min）
首次诊断准确率≥ 70%
部署复杂度Docker Compose 一键启动，5 分钟内完成

1.4 参考项目

OW

Open WebUI

开源 Chat UI 平台，作为本系统的前端基座。提供对话界面、文件上传、Markdown 渲染、用户管理、Filter/Tool 插件机制。

https://github.com/open-webui/open-webui

02. 用户场景

角色场景期望
运维工程师凌晨收到告警，上传多节点日志 + 描述"Redis 集群不可用"系统输出根因 + 修复命令 + 时间线
开发工程师收到报错截图（Java 堆栈），上传截图 + 描述"登录接口 500"OCR 识别 → 异常分析 → 修复建议
技术主管需要标准化故障报告归档结构化 Markdown 报告（根因/影响/预防）

03. 功能需求

3.1 信息采集

能力说明优先级
文本描述对话框输入故障描述P0
日志文件.log/.txt/.out，≤ 50MBP0
报错截图.png/.jpg，OCR 识别P0
压缩包.zip/.tar.gz，自动解压P1

3.2 智能预处理

  • 日志：识别时间戳/级别，提取 ERROR + 堆栈，聚合去重
  • 截图：OCR 文字识别（中英文），提取报错关键信息
  • 智能裁剪：超长日志保留故障窗口 + ERROR 全量，控制 Token 预算

3.3 领域知识 Skills（语义路由）

大模型语义路由（类 Claude Code Skills 机制）

每个 Skill 有 description 描述其适用场景。所有 Skill 描述注入 System Prompt 形成"目录"，由大模型自行判断当前场景激活哪些 Skills。不依赖关键词精确匹配。

  • 内置 8 个 Skills：Redis / MongoDB / MySQL / Docker / K8s / Java / Node.js / Network
  • 每个 Skill 包含：适用场景描述 · 排查步骤 · 常见故障模式 · 修复模板
  • 支持热加载和管理 API
  • 领域边界：若用户问题不在任何 Skill 覆盖范围内，系统直接回复"当前不支持该领域的故障诊断"，不做通用回答
  • 自进化：诊断完成后模型可建议新的 Skill 草案，管理员审核通过后入库，系统知识持续积累
非 Skills 覆盖范围 → 拒绝回答

本系统定位为领域专用诊断工具，非通用聊天机器人。当模型判断用户问题与所有已注册 Skills 的 description 均不相关时，回复标准拒绝语："抱歉，当前故障类型不在系统支持范围内。已支持领域：[领域列表]"。可通过 System Prompt 严格约束。

3.4 Agent 工具调用（深入探索）

混合架构：快速预处理 + Agent 工具迭代（类 Cursor Agent 模式）

首次分析基于预处理摘要快速给出诊断；如果模型判断证据不足，可主动调用工具深入探索日志——grep 搜索、获取上下文、按时间筛选、编写脚本统计，类似 Cursor Agent 的自主探索能力。

预定义安全工具

工具说明优先级
grep_log正则搜索已上传日志，返回匹配行 + 上下文P0
get_context获取指定行号前后 N 行上下文P0
time_window按时间范围筛选日志条目P0
count_errors聚合统计错误模式（Top N）P0
list_files列出当前会话已上传的所有文件P0

沙箱 Shell（灵活分析）

工具说明优先级
run_script在安全沙箱中执行 Bash/Python 脚本，可自由组合 grep/awk/sort 等命令，或编写统计脚本P1
  • 沙箱限制：仅能访问本次会话上传文件，禁止网络、超时 30s、输出 ≤ 50KB
  • 命令白名单：grep / awk / sed / sort / uniq / wc / head / tail / cat / python3 / jq
  • 模型可自行决定写统计脚本（如错误频率直方图、跨文件关联分析）

3.5 AI 诊断 & 报告输出

  • 流式输出结构化 Markdown 报告：故障概况 → 三层根因 → 排查路径 → 时间线 → 修复建议 → 影响范围 → 预防措施
  • 支持多轮追问，上下文保持；追问时模型可继续调用工具深入分析

04. 交互流程

4.1 两阶段混合诊断流程

flowchart LR
    A["用户输入\n描述+文件"] --> B["Phase 1\n预处理+Skills注入"]
    B --> C["大模型首次分析"]
    C --> D{"证据充分?"}
    D -->|是| E["输出报告"]
    D -->|否| F["Phase 2\n调用工具深入"]
    F --> G["grep/脚本/时间筛选"]
    G --> H["观察结果"]
    H --> D
    E --> I{"追问?"}
    I -->|是| C
    I -->|否| J["结束"]

4.2 文件处理分支

flowchart TD
    Upload["上传文件"] --> Detect{"类型"}
    Detect -->|日志| Parse["解析: 级别/堆栈/聚合"]
    Detect -->|压缩包| Unzip["解压"] --> Parse
    Detect -->|截图| OCR["OCR 识别"]
    Parse --> Build["构建增强 Prompt"]
    OCR --> Build

4.3 Prompt 结构（语义路由）

System Prompt:
  ├── 角色 + 输出格式要求
  └── Skills 目录（各 Skill 的 description + 排查知识）
      → 模型自主选择相关 Skill 引用

User Prompt:
  ├── 故障描述
  ├── 日志摘要（ERROR + 堆栈 + 高频模式）
  └── OCR 识别结果

05. 非功能需求

维度要求
性能预处理 ≤ 3s（不含 LLM 推理）
部署Docker Compose 一键启动，无需外部数据库（SQLite 嵌入式）
存储Skills 使用 Markdown 文件；聊天记录和审计日志使用 SQLite
安全Agent 沙箱隔离 + 上传文件临时目录（每月初清理）+ API Key 环境变量注入
扩展Skills 热加载；模型可切换（OpenAI 兼容接口）
