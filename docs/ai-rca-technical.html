03. Skills 语义路由设计

3.1 核心思路

大模型语义路由 — 类 Claude Code agent_skills 机制

不在后端做关键词匹配判断。而是：① 将所有 Skill 的 description（适用场景）+ 完整知识注入 System Prompt 形成"目录" → ② 大模型阅读故障上下文后自主选择激活哪些 Skills 的知识。

flowchart LR
    A["加载全部 Skills"] --> B["组装 Skill 目录\n注入 System Prompt"]
    B --> C["大模型阅读\n故障上下文"]
    C --> D["自主选择\n激活 1~3 个 Skills"]
    D --> E["引用对应知识\n输出诊断报告"]

3.2 Skill 文件格式（Markdown）

# skills/redis.md
---
id: redis
name: Redis 故障诊断
description: 当故障涉及 Redis 连接失败、主从切换、哨兵、
  集群脑裂、OOM、持久化等场景时使用此 Skill。
signal_words: [redis, 6379, sentinel]
---

## 排查步骤
1. 检查进程状态 ...
2. 查看 redis-server 日志 ...

## 常见故障模式
- **主从切换失败**: ...
- **内存 OOM**: ...

## 修复模板
- `redis-cli SENTINEL failover mymaster`
- ...

使用 YAML Front Matter + Markdown 正文。description 是核心字段，供大模型语义路由判断。signal_words 仅在 Skill 数量很多时做粗粒度预筛选。文件可直接 Git 管理和手动编辑。

3.4 Skills 自进化 — 审核入库机制

模型建议 + 管理员审核 → 新 Skill 入库

诊断结束时，模型评估本次故障是否涉及新的故障模式。如果当前 Skills 未覆盖，模型自动生成"Skill 建议草案"，待管理员审核后正式入库。

flowchart LR
    A["模型诊断完成"] --> B{"故障模式是否\n已被 Skill 覆盖？"}
    B -->|是| C["正常结束"]
    B -->|否| D["生成 Skill 建议草案\n(id/name/description/steps)"]
    D --> E["存入待审队列\n(SQLite pending_skills)"]
    E --> F["管理员审核\nAdmin API/UI"]
    F -->|通过| G["写入 skills/ 目录\n立即热加载生效"]
    F -->|拒绝| H["标记为已拒绝\n记录原因"]

04. Open WebUI 集成方式

4.1 Filter Function (inlet)

利用 Open WebUI 的 Filter Function 机制，在消息到达 LLM 前拦截并增强。伪代码：

# OpenWebUI Filter Plugin — 核心逻辑伪代码
async def inlet(body, __files__):
    user_msg = body.messages[-1].content
    # 1. 调用 RCA Backend 预处理
    result = await http_post(BACKEND + "/analyze", user_msg, __files__)
    # 2. 注入增强 Prompt（含 Skills 目录）
    body.messages.insert(0, system(result.enhanced_prompt.system))
    body.messages[-1].content = result.enhanced_prompt.user
    return body

4.2 Tool Function（Agent 工具调用）

利用 Open WebUI 的 Tool Function 机制，让模型在需要时主动调用工具。伪代码：

# OpenWebUI Tool Plugin — 注册工具供模型调用
class Tools:
    def grep_log(self, pattern: str, file: str = "", context: int = 3):
        """正则搜索已上传日志，返回匹配行+上下文"""
        return call_backend("/tools/grep", {pattern, file, context})

    def run_script(self, script: str, lang: str = "bash"):
        """在沙箱中执行分析脚本（bash/python3）"""
        return call_backend("/tools/exec", {script, lang})

    def time_window(self, start: str, end: str, level: str = ""):
        """按时间范围筛选日志条目"""
        return call_backend("/tools/time_window", {start, end, level})

06. Agent 沙箱设计

6.1 架构

run_script 工具通过独立 Docker 容器执行用户脚本，与宿主隔离。

flowchart LR
    Model["大模型调用\nrun_script"] --> Backend["RCA Backend"]
    Backend --> Create["创建沙箱容器\n挂载会话文件"]
    Create --> Exec["执行脚本\n超时 30s"]
    Exec --> Collect["收集 stdout\n截断 50KB"]
    Collect --> Return["返回结果"]

6.2 安全约束

约束实现方式
网络隔离--network none
文件系统--read-only + tmpfs 工作目录 + 会话文件只读挂载
命令白名单容器内仅安装 grep/awk/sed/sort/uniq/wc/head/tail/cat/python3/jq
资源限制CPU 0.5 核、内存 256MB、磁盘写入 100MB
单次超时30s 硬超时 kill（单个工具执行）
诊断总超时300s（5min）整体诊断兜底，超时强制基于已有信息输出报告
输出截断stdout ≤ 50KB，超长截断并标注
审计日志所有执行记录（脚本内容 + 结果）持久化存储
管理员开关可通过环境变量 ENABLE_SANDBOX_SHELL=false 禁用

6.3 Prompt 工具指引 & 领域约束

System Prompt 中增加工具使用说明 + 领域边界约束：

## 领域约束（严格遵守）
你是专业运维故障诊断助手。仅回答与以下领域相关的故障问题：
{已注册 Skills 列表及 description}

若用户问题不属于上述任何领域，直接回复：
"抱歉，当前故障类型不在系统支持范围内。已支持领域：[列表]"
不要尝试回答超出领域的问题。

## 可用工具
- grep_log(pattern, file?, context?): 正则搜索日志
- get_context(file, line, before?, after?): 查看某行上下文
- time_window(start, end, level?): 按时间范围筛选
- count_errors(file?, top_n?): 聚合统计错误
- list_files(): 查看可用文件
- run_script(script, lang?): 执行分析脚本(bash/python3)

## 工作流程
1. 先判断问题是否在支持领域内
2. 基于预处理摘要给出初步诊断
3. 证据不足时主动调用工具获取更多信息
4. 每次工具调用后更新分析判断
5. 最终输出结构化诊断报告

08. 风险与对策

风险对策
超长日志超 Token智能裁剪：保留 ERROR + 堆栈 + 故障窗口，分片处理
OCR 准确率低图片预处理增强；后续可接入视觉大模型直接读图
模型 API 不可用配置备用端点（DeepSeek/GLM-4），环境变量切换
文件安全类型白名单 + 临时目录 + 自动清理 + 大小限制
沙箱逃逸--network none + --read-only + 命令白名单 + seccomp 限制
工具调用死循环单次会话工具调用次数上限（默认 20 次）
脚本 Token 爆炸输出截断 50KB + 模型提示"结果已截断"
