Open WebUI 启动手册

Open WebUI 本地启动操作手册 v0.9.5

涵盖项目架构、环境准备、前后端启动、Docker 部署与常见问题排查的完整指南

📌 01. 项目概览

Open WebUI 是一个功能丰富的自托管 AI 平台，支持 Ollama 和 OpenAI 兼容 API。项目采用前后端分离架构，生产环境下由后端统一服务。

技术栈总览

层次技术版本
前端框架Svelte 5 + SvelteKit 2最新
构建工具Vite 5^5.4.21
CSS 框架Tailwind CSS 4 + PostCSS^4.0.0
后端框架FastAPI + Uvicorn0.135.1 / 0.41.0
ORMSQLAlchemy 2.0（同步+异步）2.0.48
数据库迁移Alembic + Peewee-migrate（遗留）1.18.4
默认数据库SQLite（支持 PostgreSQL）—
实时通信Socket.IO（python-socketio）5.16.1
包管理npm（前端）/ uv+pip（后端）—

🎨 04. 前端启动（SvelteKit）

前端使用 SvelteKit + Vite 构建，开发模式下启动 Vite Dev Server，生产模式下构建为静态文件由后端托管。

开发模式启动

❗ 前提条件 前端开发模式必须先启动后端。前端代码硬编码了开发模式 API 地址为 http://<hostname>:8080，如果后端未启动，页面会跳转到 /error 显示 "Backend Required"。
1
安装前端依赖 
cd /opt/open-webui

# 安装 npm 依赖（需要 --force 解决 peer dependency 冲突）
npm install --force

# 或 CI 环境
npm ci --force
⚠️ 为什么需要 --force？ TipTap v3 富文本编辑器存在 peer dependency 版本冲突，属于已知问题。使用 --force 可以安全忽略。
2
启动 Vite 开发服务器 
# 默认端口 5173
npm run dev

# 或指定端口 5050
npm run dev:5050
💡 首次启动注意 npm run dev 会先执行 pyodide:fetch 脚本，下载 Pyodide Python 运行时到 static/pyodide/。首次下载约 50MB，后续启动会跳过。如果网络较慢，可先单独执行 npm run pyodide:fetch。
3
访问开发页面 
# 浏览器打开
http://localhost:5173

前端如何连接后端

前端没有 Vite proxy 配置，而是直接通过 CORS 跨域请求后端。关键逻辑在 src/lib/constants.ts 中：

// 开发模式：固定请求 http://<当前hostname>:8080
export const WEBUI_HOSTNAME = browser
  ? (dev ? `${location.hostname}:8080` : ``)
  : '';
export const WEBUI_BASE_URL = browser
  ? (dev ? `http://${WEBUI_HOSTNAME}` : ``)
  : ``;

// 生产模式：使用相对路径（同域），WEBUI_BASE_URL 为空字符串
export const WEBUI_API_BASE_URL = `${WEBUI_BASE_URL}/api/v1`;
💡 开发模式连接关系
前端地址后端地址CORS 配置
http://localhost:5173http://localhost:8080dev.sh 已配置允许 5173
如果后端端口不是 8080，需要修改 src/lib/constants.ts 中的端口。

生产模式构建

# 构建静态文件到 build/ 目录
npm run build

# 预览构建结果
npm run preview

构建完成后，build/ 目录会被 FastAPI 自动托管，访问后端 8080 端口即可看到完整 Web UI。

🐳 06. Docker 部署

Docker 是最推荐的生产部署方式。项目提供了完善的 Dockerfile 和多种 Docker Compose overlay 配置。

方式一：Docker Compose（推荐）

默认配置启动 Ollama + Open WebUI 双服务栈：

# 最简单的启动方式
docker compose up -d

# 或使用 Makefile
make install
docker-compose.yaml
核心内容： 
services:
  ollama:
    image: ollama/ollama:latest
    container_name: ollama
    volumes:
      - ollama:/root/.ollama
    restart: unless-stopped

  open-webui:
    build: .
    image: ghcr.io/open-webui/open-webui:main
    container_name: open-webui
    ports:
      - "3000:8080"       # 宿主机 3000 → 容器 8080
    environment:
      - OLLAMA_BASE_URL=http://ollama:11434
    volumes:
      - open-webui:/app/backend/data
    depends_on:
      - ollama
    restart: unless-stopped

Compose Overlay 组合

# 基础启动

./run-compose.sh \
  --enable-gpu[count=1] \

方式三：单容器运行（使用官方镜像）

# 基础版（连接外部 Ollama）
docker run -d -p 3000:8080 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart unless-stopped \
  ghcr.io/open-webui/open-webui:main

# CUDA 版
docker run -d -p 3000:8080 \
  --gpus all \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -v open-webui:/app/backend/data \
  --name open-webui \
  ghcr.io/open-webui/open-webui:cuda

# 内置 Ollama 版
docker run -d -p 3000:8080 \
  -v open-webui:/app/backend/data \
  -v ollama:/root/.ollama \
  --name open-webui \
  ghcr.io/open-webui/open-webui:ollama

🔧 08. 常见问题排查

收录本地开发和部署中高频遇到的问题及解决方案。

后端启动失败

问题：ModuleNotFoundError

ModuleNotFoundError: No module named 'open_webui'
✅ 解决方案 确保在 backend/ 目录下执行启动脚本，且已激活虚拟环境： 
source /opt/open-webui/.venv/bin/activate
cd /opt/open-webui/backend
bash dev.sh

问题：pip install 编译失败

error: command 'gcc' failed
# 或
fatal error: Python.h: No such file or directory
✅ 解决方案 安装系统编译依赖： 
# Ubuntu/Debian
sudo apt install build-essential python3.11-dev

# macOS
xcode-select --install

问题：端口 8080 被占用

ERROR: [Errno 98] Address already in use
✅ 解决方案 
# 查找占用进程
lsof -i :8080
# 或使用其他端口
PORT=9090 bash dev.sh
注意：如果修改后端端口，前端 src/lib/constants.ts 中硬编码的 8080 也需要同步修改。

前端启动失败

问题：npm install 报 peer dependency 冲突

npm ERR! ERESOLVE unable to resolve dependency tree
✅ 解决方案 TipTap v3 的已知问题，使用 --force 标志： 
npm install --force

问题：页面显示 "Backend Required"

✅ 解决方案 前端必须在后端运行后才能正常使用。请确保：
  1. 后端已在 8080 端口运行
  2. curl http://localhost:8080/health 返回 {"status":true}
  3. 后端 dev.sh 中的 CORS 配置包含前端地址

问题：Pyodide 下载缓慢

✅ 解决方案 npm run dev 首次会下载 Pyodide 运行时（~50MB）。可以：
  • 使用代理：HTTPS_PROXY=http://... npm run pyodide:fetch
  • 手动下载后放入 static/pyodide/
  • 如果不需要浏览器内 Python 执行，可以暂时跳过（不影响主功能）

Docker 相关

问题：容器内无法连接宿主机 Ollama

✅ 解决方案 
# 使用 host.docker.internal（Linux 需要 extra_hosts 配置）
docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  ghcr.io/open-webui/open-webui:main

# docker-compose.yaml 已包含此配置
extra_hosts:
  - host.docker.internal:host-gateway

问题：Docker 构建内存不足

✅ 解决方案 完整构建需要 4GB+ 内存。可使用精简模式跳过模型预下载： 
docker build --build-arg USE_SLIM=true -t open-webui .

🖥 10. 使用 PyCharm 启动后端

如果你习惯使用 PyCharm IDE 进行开发，可以通过配置 Run Configuration 来启动和调试后端。下面提供三种配置方式。

前提：配置 Python 解释器

1
打开项目

用 PyCharm 打开 /opt/open-webui 根目录（不是 backend/ 子目录）。

2
配置 Python 解释器

File → Settings → Project → Python Interpreter

  • 点击齿轮图标 → Add Interpreter → Add Local Interpreter
  • 选择 Existing，路径指向：/opt/open-webui/.venv/bin/python
  • 如果还没创建虚拟环境，选择 New，Base interpreter 选 Python 3.11
💡 提示 确保解释器使用 Python 3.11.x 或 3.12.x。PyCharm 会自动识别 .venv 目录。
3
安装依赖

在 PyCharm Terminal 中执行（或通过 PyCharm 的包管理界面安装）：

pip install -r backend/requirements.txt -i https://mirrors.aliyun.com/pypi/simple/

方式一：Uvicorn Run Configuration 推荐

直接配置 Uvicorn 启动 FastAPI 应用，支持断点调试。

1
创建 Run Configuration

Run → Edit Configurations → + → Python

2
填写配置项
配置项值
NameOpen WebUI Backend (Dev)
Module nameuvicorn（选择 "Module name" 而非 "Script path"）
Parametersopen_webui.main:app --host 0.0.0.0 --port 8080 --reload
Working directory/opt/open-webui/backend
Python interpreter选择项目的 .venv 解释器
3
配置环境变量

在 Run Configuration 的 Environment variables 中添加：

CORS_ALLOW_ORIGIN=http://localhost:5173;http://localhost:8080
WEBUI_SECRET_KEY=dev-secret-key-12345
OLLAMA_BASE_URL=http://localhost:11434
💡 设置方法 点击 Environment variables 右侧的文件夹图标，在弹出的对话框中逐行添加键值对。也可以点击右下角 ... 从 .env 文件加载。
4
运行或调试
  • 点击 Run ▶ 正常启动
  • 点击 Debug 🐛 启动调试模式（可设断点）
⚠️ 调试模式注意 Debug 模式下 --reload 参数可能导致断点失效（Uvicorn reload 会 fork 子进程）。如果需要断点调试，建议去掉 --reload 参数：
Parameters: open_webui.main:app --host 0.0.0.0 --port 8080

直接运行 dev.sh 脚本，最简单但不支持断点调试。

配置项值
NameOpen WebUI dev.sh
Script path/opt/open-webui/backend/dev.sh
Interpreter path/bin/bash
Working directory/opt/open-webui/backend

Run → Edit Configurations → + → Shell Script，然后按上表配置。

如果使用 PyCharm Professional 版，可以使用内置的 FastAPI 运行配置。

Sources Root 配置

为了让 PyCharm 正确解析 import open_webui，需要将 backend 目录标记为 Sources Root：

  1. 在项目视图中右键 backend 目录
  2. 选择 Mark Directory as → Sources Root
  3. 此时 backend 目录图标会变为蓝色
❗ 不标记 Sources Root 的后果 PyCharm 会在所有 from open_webui import ... 处报红色 "Unresolved reference" 错误，虽然不影响运行但会干扰开发体验。
