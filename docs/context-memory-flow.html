📌 01. 总览

在 Open WebUI 的同一个会话中，所有历史消息都会作为上下文发送给大模型。上下文的"真相来源"是后端数据库，而非前端请求体。

以下是完整的数据流概览，覆盖前端消息收集、后端上下文组装、System Prompt 注入、工具调用循环等全流程。

🖥️ 02. 前端消息管理

前端使用树形结构管理消息，支持分支和重新生成。核心数据结构和关键函数如下。

消息树结构

前端的 history 变量是一个 Map + 当前节点指针，而非简单数组：

src/lib/components/chat/Chat.svelte:164-167
let history = {
  messages: {},    // Map<id, Message>  每条消息含 parentId / childrenIds
  currentId: null  // 当前激活的消息 ID
};

历史消息收集

核心函数 createMessagesList 从当前 messageId 沿 parentId 向上回溯，再 reverse 成时间顺序：

src/lib/utils/index.ts:1304-1318
export const createMessagesList = (history, messageId) => {
  const list = [];
  let currentId = messageId;
  while (currentId !== null && currentId !== undefined) {
    const message = history.messages[currentId];
    if (message === undefined) break;
    list.push(message);
    currentId = message.parentId;
  }
  return list.reverse();
};

请求体构造

持久化会话和临时会话的关键差异：

持久化会话（默认）前端 messages 仅包含 system prompt，历史由后端从 DB 加载
临时会话前端发送完整对话历史，chat_id 以 local: 开头，不写 DB

从 DB 加载历史消息

async def load_messages_from_db(chat_id, message_id):
    messages_map = await Chats.get_messages_map_by_chat_id(chat_id)
    db_messages = get_message_list(messages_map, message_id)
    return [{k: v for k, v in msg.items()
             if k in ('role', 'content', 'output', 'files')}
            for msg in db_messages]

还原工具调用历史

DB 中 assistant 消息的工具调用存在 output 数组中（Responses API 格式），发送给 LLM 前需要还原为标准 Chat Completions 格式：

backend/open_webui/utils/middleware.py:2269-2297
def process_messages_with_output(messages):
    for message in messages:
        if message.get('role') == 'assistant' and message.get('output'):
            # output 数组 → assistant.tool_calls + tool 消息
            output_messages = convert_output_to_messages(message['output'])
            processed.extend(output_messages)
        else:
            processed.append(message)
    return processed

convert_output_to_messages 的转换规则：

output 中的类型转换为
function_callassistant 消息 + tool_calls 数组
function_call_output{ role: 'tool', tool_call_id, content }
message普通 assistant 文本消息
reasoning按 provider 格式嵌入思考过程

        if message.get('role') == 'system':

    merged = {'role': 'system', 'content': '\n'.join(system_contents)}

🔧 07. 工具调用循环

当 LLM 返回 tool_calls 时，后端会执行工具并将结果回注 messages，然后再次调用 LLM。这个循环会持续到 LLM 不再请求工具调用为止。

sequenceDiagram
    participant MW as middleware.py
process_chat_response
    participant Tool as 工具函数
(grep_log, get_context, ...)
    participant LLM as LLM Provider

    MW->>LLM: messages[] (首次调用)
    LLM-->>MW: response 含 tool_calls
    MW->>Tool: 执行 grep_log(pattern, ...)
    Tool-->>MW: 工具结果
    MW->>MW: 结果写入 output 数组
    MW->>MW: convert_output_to_messages()
    Note over MW: messages += [assistant(tool_calls), tool(result)]
    MW->>LLM: messages[] (含工具结果，第2次调用)
    LLM-->>MW: 最终文本回复（无 tool_calls）
    MW->>MW: upsert_message_to_chat()

工具结果的存储和还原机制：

阶段格式存储位置
运行时（LLM 交互）assistant.tool_calls + { role: 'tool', content }内存中的 messages 数组
持久化（写 DB）output 数组（Responses API 格式）chat_message 表 / chat.chat JSON
下次加载（读 DB）convert_output_to_messages() 还原从 DB → 标准 Chat Completions 格式

📏 08. 上下文截断策略

Open WebUI 主聊天链路没有基于 token 的历史消息截断逻辑。完整的 parentId 链都会送入 LLM，受模型 Provider 自身的 context window 限制。

机制位置作用
max_tokens请求 params → Provider生成长度限制，非上下文截断
truncatepayload.py → OllamaOllama 特有参数
truncate_contentutils/task.py后台任务（标题/标签生成）的 prompt 截断
工具输出限制tools/builtin.pyMAX_LINE_LENGTH=500、沙箱 stdout 上限等
Memory top-kmiddleware.pyMemory 检索固定 top-k=3
实际限制当会话消息累积超过模型 context window（如 GPT-4o 128K、Claude 200K）时，Provider 会截断最早的消息或返回错误。Open WebUI 本身不做主动截断。
